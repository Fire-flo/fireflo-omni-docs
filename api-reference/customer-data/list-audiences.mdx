---
title: "GET /v1/cdp/audiences"
description: "The account's audiences, with how many people are in each."
---

Every audience on the account, with how many people are in each and whether that is worked out. Rules are left out here; read one audience for its rules.

<Note>Needs the `cdp.audiences:read` scope.</Note>

## Request

<CodeGroup>

```bash cURL
curl "https://api.fireflo.au/v1/cdp/audiences" \
  -H "Authorization: Bearer $OMNI_API_KEY"
```

```python Python
import os

import requests

response = requests.get(
    "https://api.fireflo.au/v1/cdp/audiences",
    headers={"Authorization": f"Bearer {os.environ['OMNI_API_KEY']}"},
)
print(response.status_code, response.json())
```

```javascript Node
const response = await fetch("https://api.fireflo.au/v1/cdp/audiences", {
  headers: {
    Authorization: `Bearer ${process.env.OMNI_API_KEY}`,
  },
});
console.log(response.status, await response.json());
```

</CodeGroup>

## Response

`200 OK` — every audience, in `data`. `members` is how many are in it; `refreshed_at` is when that was last worked out. 

| `status` | Meaning |
| :--- | :--- |
| `building` | Who's in is being worked out. `members` is what it was before. |
| `ready` | Worked out; people join and leave as they match. |
| `failed` | It couldn't be worked out: `error` says why. |

## Errors

Every refusal is `{"error": {"code", "message", "field"}}`; `field` is there when one input is at fault.

| Status | Error code | When |
| :--- | :--- | :--- |
| 403 | `scope_missing` | The key doesn't have the `cdp.audiences:read` scope. |
| 404 | `module_off` | The account doesn't have Customer data on. |

Any request can also be refused for its key, its account or its rate (`key_required`, `invalid_key`, `account_suspended`, `plan_excludes_api`, `address_not_allowed`, `rate_limited`); see [the overview](/api-reference/overview).
