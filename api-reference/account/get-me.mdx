---
title: "GET /v1/me"
description: "Which account and plan a key belongs to, and what the key may do."
---

The first call an integration makes: it answers with the key's account and plan, and the key itself — its scopes, its allowed addresses and when it expires. The key's secret is never shown again; `prefix` is the start of it, to tell keys apart.

<Note>Any valid key can call this: it needs no scope.</Note>

## Request

<CodeGroup>

```bash cURL
curl https://api.fireflo.au/v1/me \
  -H "Authorization: Bearer $OMNI_API_KEY"
```

```python Python
import os

import requests

response = requests.get(
    "https://api.fireflo.au/v1/me",
    headers={"Authorization": f"Bearer {os.environ['OMNI_API_KEY']}"},
)
print(response.status_code, response.json())
```

```javascript Node
const response = await fetch("https://api.fireflo.au/v1/me", {
  headers: {
    Authorization: `Bearer ${process.env.OMNI_API_KEY}`,
  },
});
console.log(response.status, await response.json());
```

</CodeGroup>

## Errors

Every refusal is `{"error": {"code", "message", "field"}}`; `field` is there when one input is at fault.

| Status | Error code | When |
| :--- | :--- | :--- |

Any request can also be refused for its key, its account or its rate (`key_required`, `invalid_key`, `account_suspended`, `plan_excludes_api`, `address_not_allowed`, `rate_limited`); see [the overview](/api-reference/overview).
