---
title: "POST /v1/catalogue/orders/{order_id}/fulfil"
description: "Mark an order fulfilled once it has gone out."
---

Marks an order fulfilled — it has gone out to the customer. Nothing is sent to them. Webhooks get `order.fulfilled`. Asking again for the status it already has changes nothing and sends nothing.

<Note>Needs the `catalogue.orders:write` scope.</Note>

## Path parameters

| Field | Type | Required | Notes |
| :--- | :--- | :--- | :--- |
| `order_id` | string | Yes | The order's id. |

## Request

<CodeGroup>

```bash cURL
curl -X POST "https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34/fulfil" \
  -H "Authorization: Bearer $OMNI_API_KEY"
```

```python Python
import os

import requests

response = requests.post(
    "https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34/fulfil",
    headers={"Authorization": f"Bearer {os.environ['OMNI_API_KEY']}"},
)
print(response.status_code, response.json())
```

```javascript Node
const response = await fetch("https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34/fulfil", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.OMNI_API_KEY}` },
```

## Response

`200 OK` — the order, now `fulfilled`. `status` is `new`, `confirmed`, `declined`, `fulfilled` or `cancelled`. `source` is where it came from: `cart` (a WhatsApp cart), `agent` (an AI agent's draft, approved by a person), `person` (made by hand in the panel) or `api`. `channel` is the channel it came in on, where replies about it go. Each line keeps its own copy of the name and price, so a later change to the product doesn't rewrite it; `product` is the product's id, or `null` for a SKU the catalogue doesn't have. Money is in minor units.

## Errors

Every refusal is `{"error": {"code", "message", "field"}}`; `field` is there when one input is at fault.

| Status | Error code | When |
| :--- | :--- | :--- |
| 409 | `invalid_state` | The order was declined or cancelled, so it can't be fulfilled. `message` says which. |
| 404 | `not_found` | No order of this account's has that id. |
| 404 | `module_off` | The account doesn't have Catalogue on. |
| 403 | `scope_missing` | The key doesn't have the `catalogue.orders:write` scope. |

Any request can also be refused for its key, its account or its rate (`key_required`, `invalid_key`, `account_suspended`, `plan_excludes_api`, `address_not_allowed`, `rate_limited`); see [the overview](/api-reference/overview).
