One order, with its history.

<Note>Needs the `catalogue.orders:read` scope.</Note>

## Path parameters

| Field | Type | Required | Notes |
| :--- | :--- | :--- | :--- |
| `order_id` | string | Yes | The order's id. |

## Request

<CodeGroup>

```bash cURL
curl "https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34" \
  -H "Authorization: Bearer $OMNI_API_KEY"
```

```python Python
import os

import requests

response = requests.get(
    "https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34",
    headers={"Authorization": f"Bearer {os.environ['OMNI_API_KEY']}"},
)
print(response.status_code, response.json())
```

```javascript Node
const response = await fetch("https://api.fireflo.au/v1/catalogue/orders/9d4e2b7a-1c3f-4a8e-b6d5-0f2e7c9a1b34", {
  headers: { Authorization: `Bearer ${process.env.OMNI_API_KEY}` },
});
console.log(response.status, await response.json());
```

</CodeGroup>

## Response

`200 OK` — the order. `status` is `new`, `confirmed`, `declined`, `fulfilled` or `cancelled`. `source` is where it came from: `cart` (a WhatsApp cart), `agent` (an AI agent's draft, approved by a person), `person` (made by hand in the panel) or `api`. `channel` is the channel it came in on, where replies about it go. Each line keeps its own copy of the name and price, so a later change to the product doesn't rewrite it; `product` is the product's id, or `null` for a SKU the catalogue doesn't have. Money is in minor units. `history` is what happened to it, oldest first: each entry says what, who (`by` — a person, "FireFlo", or a key, as in "API · Shopify sync"), and when.

## Errors

Every refusal is `{"error": {"code", "message", "field"}}`; `field` is there when one input is at fault.

| Status | Error code | When |
| :--- | :--- | :--- |
| 404 | `not_found` | No order of this account's has that id. |
| 404 | `module_off` | The account doesn't have Catalogue on. |
| 403 | `scope_missing` | The key doesn't have the `catalogue.orders:read` scope. |

Any request can also be refused for its key, its account or its rate (`key_required`, `invalid_key`, `account_suspended`, `plan_excludes_api`, `address_not_allowed`, `rate_limited`); see [the overview](/api-reference/overview).
