---
title: "POST /v1/agents/plans/{plan_id}/approve"
description: "Approve a plan waiting for approval, with optional edits to its steps."
---

Approves a plan that is `awaiting_approval`, exactly as **Approve** on the panel does: what you approve is what runs. You can change a step first — a message's wording, a note, an amount — in the fields its `editable` lists; each edit is checked again as if the agent had planned it. Steps that were due run now; later ones when they fall due.

<Note>Needs the `agents.plans:write` scope.</Note>

## Path parameters

| Field | Type | Required | Notes |
| :--- | :--- | :--- | :--- |
| `plan_id` | integer | Yes | The plan's id. |

## Body

| Field | Type | Required | Notes |
| :--- | :--- | :--- | :--- |
| `steps` | array | No | Edits: `{ "id": <step id>, <field>: <new value> }` for steps still `pending`. Fields a step doesn't list in `editable` are ignored. |
| `note` | string | No | A note kept with the decision. Up to 1,000 characters. |

## Request

<CodeGroup>

```bash cURL
curl -X POST "https://api.fireflo.au/v1/agents/plans/4812/approve" \
  -H "Authorization: Bearer $OMNI_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: approve-4812" \
  -d '{
    "steps": [
      {
        "id": 20931,
        "body": "Hi Neha, for 40 units we can do ₹6,350 each, delivered to Ludhiana within 10 days. Shall I send the revised quote?"
      }
    ],
    "note": "Fine — keep delivery at 10 days."
  }'
```

## Errors

Every refusal is `{"error": {"code", "message", "field"}}`; `field` is there when one input is at fault.

| Status | Error code | When |
| :--- | :--- | :--- |
| 400 | `invalid_request` | `steps` isn't a list, or `note` is too long; `field` names it. |
| 404 | `not_found` | No plan of this account's has that id. |
| 409 | `invalid_state` | The plan isn't waiting for approval, or an edit isn't allowed — the message names the step. |
| 404 | `module_off` | The account doesn't have AI agents on: they aren't in its plan, or are switched off for it. |
| 403 | `scope_missing` | The key doesn't have the `agents.plans:write` scope. |

Any request can also be refused for its key, its account or its rate (`key_required`, `invalid_key`, `account_suspended`, `plan_excludes_api`, `address_not_allowed`, `rate_limited`); see [the overview](/api-reference/overview).
